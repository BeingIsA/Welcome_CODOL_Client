# 终版原包资源

正式启动从 `client/resources/v1649370/packed/` 读取 1649370 版资源。这个目录包含 974 个 IFS、包外运行依赖、语言包、视频及 `packed-index.json.gz`。菜单补丁随宿主放在 `client/manifests/offline-menu-patches.json`。

## 运行和核验

在 `client/` 运行 `start_client.cmd`。新槽位首次启动时，宿主在 Windows Cloud Files 注册按需目录并创建占位文件。游戏读取尚未填充的文件时，读取器从本机已有的原包取成员，核对长度和 SHA-256，再完整交付该文件。配置、模型、图像和音频使用终版散装解码，FF 保留游戏可读的封包格式。退出时断开会话连接并关闭读取器，槽位保留已完成的视图和已填充内容。相同版本再次租用该槽位时直接重连。并发游戏各用独立槽位，各自占用缓存空间。

```powershell
python -B -X utf8 .\tools\launch_client.py --prepare-only --verify-resources
```

这条命令对索引列出的实体文件计算 SHA-256，验证启动目录并退出。游戏进程的实际取件记录保存在 `workspaces/offline-runs/<会话名>/packed-fetch.jsonl`。

## 准备与发布

开发机使用随版本维护的 `packed-index.json.gz`，从匹配的原安装导入原文件。正文按索引逐项校验，已存在且通过校验的文件可以复用。从项目根目录运行：

```powershell
python -B -X utf8 client/tools/prepare_packed_resources.py --source "Original Client"
```

资源分卷包含独立索引、实体文件、`bin/v1649370/packed-reader/` 下的读取组件及菜单补丁。使用 Bandizip 构建分卷并校验压缩包。从项目根目录运行：

```powershell
python -B -X utf8 client/tools/package_resources.py --output D:/packages/resources.zip
```

将同一次构建的所有分卷放在一起，从最后的 `.zip` 解压到 `client/`。程序依赖、版本镜像、守卫和服务器配置随宿主交付。
